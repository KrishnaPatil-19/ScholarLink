## 1. Executive Summary

| Item | Code-derived finding |

| Project name | ScholarLink, shown in `README.md`, `templates/main.html`, and `templates/navbar.html`. |

## 5. Database Design

### `User`

Extends `django.contrib.auth.models.AbstractUser`.

| Field | Type | Rules |
| --- | --- | --- |
| inherited auth fields | Django auth fields | Includes username, password, first/last name, staff/superuser flags, groups, permissions, etc. |
| `name` | `CharField(max_length=200, null=True)` | Optional display name. |
| `email` | `EmailField(unique=True, null=True)` | Email login field; unique at database/model level. |
| `bio` | `TextField(null=True)` | Optional profile bio. |
| `avatar` | `ImageField(null=True, default="avatar.svg")` | Stored under `MEDIA_ROOT`; no upload subdirectory is set. |

Model auth settings: `USERNAME_FIELD='email'`, `REQUIRED_FIELDS=[]`.

### `Topic`

| Field | Type | Rules |
| --- | --- | --- |
| `name` | `CharField(max_length=200)` | No unique constraint. |

`__str__` returns `name`.

### `Hub`

| Field | Type | Rules |
| --- | --- | --- |
| `name` | `CharField(max_length=200)` | No unique constraint. |
| `slug` | `SlugField(max_length=220, unique=True, null=True, blank=True)` | Unique when supplied. Source does not auto-populate it. |
| `description` | `TextField(null=True, blank=True)` | Optional. |
| `avatar` | `ImageField(null=True, blank=True, default="hub.svg")` | No upload subdirectory. |
| `followers` | `ManyToManyField(User, related_name='followed_hubs', blank=True)` | No web view currently follows/unfollows hubs. |
| `created` | `DateTimeField(auto_now_add=True)` | Creation timestamp. |

Ordering: newest created first. `__str__` returns `name`.

### `Room`

| Field | Type | Rules |
| --- | --- | --- |
| `host` | `ForeignKey(User, SET_NULL, null=True)` | Room survives if host is deleted. Some templates assume `room.host` is not null. |
| `topic` | `ForeignKey(Topic, SET_NULL, null=True)` | Room survives if topic is deleted. |
| `hub` | `ForeignKey(Hub, SET_NULL, null=True, blank=True)` | Optional space/community. |
| `name` | `CharField(max_length=200)` | Required by model. |
| `description` | `TextField(null=True, blank=True)` | Optional. |
| `participants` | `ManyToManyField(User, related_name='participants', blank=True)` | Users are added when they post a non-flagged message. |
| `updated` | `DateTimeField(auto_now=True)` | Updates on save. |
| `created` | `DateTimeField(auto_now_add=True)` | Creation timestamp. |

Ordering: `-updated`, then `-created`. `__str__` returns `name`.

### `Message`

| Field | Type | Rules |
| --- | --- | --- |
| `user` | `ForeignKey(User, CASCADE)` | Message deleted if user deleted. |
| `room` | `ForeignKey(Room, CASCADE)` | Message deleted if room deleted. |
| `parent` | `ForeignKey('self', CASCADE, null=True, blank=True, related_name='replies')` | Supports threaded replies. |
| `body` | `TextField()` | Required by model; views strip and reject empty submissions. |
| `upvoted_by` | `ManyToManyField(User, related_name='upvoted_messages', blank=True)` | Used for score. |
| `downvoted_by` | `ManyToManyField(User, related_name='downvoted_messages', blank=True)` | Used for score. |
| `is_flagged` | `BooleanField(default=False)` | Set when off-topic check fails. |
| `is_removed` | `BooleanField(default=False)` | Flagged messages are hidden by normal room/activity queries. |
| `flag_reason` | `CharField(max_length=200, null=True, blank=True)` | Set to off-topic message text when flagged by room view. |
| `updated` | `DateTimeField(auto_now=True)` | Updates on save. |
| `created` | `DateTimeField(auto_now_add=True)` | Creation timestamp. |

Computed properties:

| Property | Logic |
| --- | --- |
| `score` | `upvoted_by.count() - downvoted_by.count()` |
| `visible_replies` | `self.replies.filter(is_removed=False)` |

Ordering: `-updated`, then `-created`. `__str__` returns first 50 characters of `body`.

Normal operation:

1. Auth creates/updates `User`.
2. Room create/update uses or creates `Topic`; optionally uses or creates `Hub`.
3. Room listing filters `Room` by topic, name, and description.
4. Room detail lists top-level non-removed messages and recursively renders non-removed replies.
5. Posting creates `Message`; off-topic messages are created but marked flagged/removed.
6. Non-flagged message posting adds the user to `Room.participants`.
7. Voting mutates message/user many-to-many tables.

## 6. Authentication and Authorization

| Area | Implementation |
| --- | --- |
| Registration | `registerPage` uses `MyUserCreationForm`, lowercases username/email, saves, authenticates by email/password, logs user in if authentication succeeds, redirects home. |
| Login | `loginPage` accepts POST `email`, `password`, optional `remember_me`; validates presence and regex; lowercases email; authenticates via `authenticate(request, email=..., password=...)`. |
| Logout | `logoutUser` calls Django `logout()` and redirects home. |
| Sessions | Settings use 2-week default age, save every request, do not expire at browser close by default, cookie secure disabled, HTTP-only enabled. Login view overrides expiry to 2 weeks for Remember Me or browser close without it. |
| Password reset | No custom password reset views/templates/routes are defined. allauth account URLs are included; availability beyond included allauth routes is not customized in source. |
| Email verification | `ACCOUNT_EMAIL_VERIFICATION='optional'`; `ACCOUNT_LOGIN_ON_EMAIL_CONFIRMATION=True`; no email backend configured. |
| Google sign-in | django-allauth Google provider installed/configured; custom templates exist for social login, signup, and cancelled login. Client ID in settings is empty. |
| Permissions | Django auth permissions exist through `AbstractUser`; no app-specific permission classes are used. |
| User roles | Anonymous, authenticated, owner, Django staff/superuser are distinguishable from code. No additional roles. |
| Ownership checks | Room update/delete require `request.user == room.host`. Message update/delete require `request.user == message.user`. Profile edit link appears only for own profile, and `updateUser` edits `request.user`. |
| Login-required views | Create/update/delete room, update/delete message, vote, update user. Room posting redirects unauthenticated users to login server-side; JavaScript also shows a modal before submit. |
| Middleware | Uses Django auth/session/CSRF/messages and allauth account middleware. No custom middleware. |

Security note: `logout/` is a GET route and performs logout without POST/CSRF.

| Off-topic moderation | Blocks/removes messages that do not match room topic tokens/synonyms. | `is_message_on_topic` checks word overlap with topic words or `TOPIC_SYNONYMS`. Flagged messages are saved with `is_flagged=True`, `is_removed=True`, `flag_reason`, and session modal text. |

| Message delete | Owner deletes message. | Deletes on POST. Replies cascade if parent is deleted because `parent` uses CASCADE. |
| Voting | Authenticated users upvote/downvote messages. | Owner cannot vote own message. Upvote removes downvote and adds upvote; downvote removes upvote and adds downvote. No toggle-off behavior. |
| Login-required modal | Frontend prevents unauthenticated posting/replying before server request. | `script.js` checks `body[data-authenticated]` on forms with `data-login-action`; shows modal. Server still enforces auth for room POST. |

## 12. Business Logic

| Rule | Source behavior |
| --- | --- |
| Email format | Regex `^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$` in views/forms. |
| Unique email | Model `unique=True`; registration form checks case-insensitive existence. |
| Unique username | Inherited unique username; registration form checks case-insensitive existence. |
| Login security message | Login failure uses generic `Invalid email or password.` |
| Search | Home searches room topic name, room name, room description by `icontains`; topics page searches topic name by `icontains`; activity sidebar only filters by room topic name. |
| Room ordering | Rooms ordered by newest updated, then newest created. |
| Message ordering | Messages ordered by newest updated, then newest created. |
| Hub ordering | Hubs ordered by newest created. |
| Topic sidebar limit | Home loads first five topics without explicit ordering. |
| Space sidebar limit | Home loads first six hubs by model ordering. |
| Recent activity limit on home | Home loads first three non-removed messages matching room topic query. |
| Threading | Room page loads top-level messages; `thread_item.html` recursively renders `visible_replies`. |
| Off-topic detection | A message is on-topic if its normalized words overlap room topic words or synonyms for topic tokens in `TOPIC_SYNONYMS`. Empty body is invalid; empty topic means message is accepted. |
| Flag/removal | Off-topic posts are still saved but hidden (`is_removed=True`) and marked flagged. |
| Participants | Posting a non-flagged message adds the user to room participants. Replies count too because same POST handler is used. |
| Voting | Users cannot vote on their own message; upvote/downvote are mutually exclusive but not toggleable to neutral through same action. |
| Ownership | Only room host may edit/delete room; only message author may edit/delete message. |
| Pagination | No pagination exists in source. |
| Ranking | No ranking beyond model ordering and message score display. Score does not affect ordering. |

## 17. REST API Requirements

Recommendation: Use Django REST Framework with token-based authentication suitable for native apps. Prefer JWT access/refresh tokens using a maintained DRF JWT package, or DRF TokenAuth if simplicity matters more than refresh-token lifecycle. Session authentication is not ideal for a Java Android client because CSRF/cookie handling complicates native flows.

Recommended endpoints:

| URL | Method | Auth | Request | Response |
| --- | --- | --- | --- | --- |
| `/api/auth/register/` | POST | Public | `name`, `username`, `email`, `password1`, `password2` | User object + tokens or success. |
| `/api/auth/login/` | POST | Public | `email`, `password` | Access/refresh token + user. |
| `/api/auth/logout/` | POST | Required | Refresh token if JWT blacklist is used | Success. |
| `/api/auth/me/` | GET | Required | None | Current user. |
| `/api/auth/me/` | PATCH | Required | `name`, `username`, `email`, `bio`, optional multipart `avatar` | Updated user. |
| `/api/topics/` | GET | Public | Query `q` | Topic list with room counts. |
| `/api/hubs/` | GET | Public | Query `q` optional | Hub list with follower counts. |
| `/api/rooms/` | GET | Public | Query `q`, `topic`, `hub`, pagination | Room cards with host/topic/hub/counts. |
| `/api/rooms/` | POST | Required | `name`, `description`, `topic`, optional `hub` | Created room. |
| `/api/rooms/<id>/` | GET | Public | None | Room detail including host/topic/hub/participants and optionally message tree. |
| `/api/rooms/<id>/` | PATCH | Host only | `name`, `description`, `topic`, optional `hub` | Updated room. |
| `/api/rooms/<id>/` | DELETE | Host only | None | 204/confirmation. |
| `/api/rooms/<id>/messages/` | GET | Public | Pagination/thread mode | Top-level messages with nested visible replies or flat list with parent ids. |
| `/api/rooms/<id>/messages/` | POST | Required | `body`, optional `parent` | Message object; if flagged, include `is_flagged`, `is_removed`, `flag_reason`. |
| `/api/messages/<id>/` | PATCH | Owner only | `body` | Updated message or validation/off-topic error. |
| `/api/messages/<id>/` | DELETE | Owner only | None | 204/confirmation. |
| `/api/messages/<id>/vote/` | POST | Required, not owner | `action`: `upvote` or `downvote` | Updated score and user's vote state. |
| `/api/users/<id>/` | GET | Public | None | Public profile. |
| `/api/users/<id>/rooms/` | GET | Public | Pagination | Hosted rooms. |
| `/api/users/<id>/messages/` | GET | Public | Pagination | Non-removed user messages/activity. |
| `/api/activity/` | GET | Public | Pagination/query | Recent non-removed messages. |

Response bodies should avoid raw `fields='__all__'` for Android. Include nested display objects where the UI needs them, for example room host username/avatar, topic name, hub name, participant count, message score, current user's vote, and ownership booleans.

## 19. Recommended Android Architecture

Recommendation for a native Java Android app:

```text
com.example.scholarlink/
|-- data/
|   |-- api/              Retrofit interfaces, auth interceptor
|   |-- model/            User, Room, Topic, Hub, Message DTOs
|   |-- repository/       AuthRepository, RoomRepository, etc.
|   `-- local/            Room cache, SharedPreferences/Security storage
|-- ui/
|   |-- auth/
|   |-- home/
|   |-- rooms/
|   |-- topics/
|   |-- activity/
|   |-- profile/
|   `-- common/
|-- util/
`-- ScholarLinkApplication.java
```

Recommended libraries:

| Need | Recommendation |
| --- | --- |
| Networking | Retrofit + OkHttp + Gson or Moshi. |
| Image loading | Glide or Coil is Kotlin-first; for Java, Glide is straightforward. |
| Local storage | Room database for caches if offline support is needed; otherwise SharedPreferences for lightweight settings. |

## 21. AI Implementation Strategy

Fastest AI-assisted path:

1. Generate DRF serializers and permissions from the existing models and view business rules.
2. Generate API tests for each existing web behavior before replacing or extending behavior.
3. Generate Android Java DTOs from finalized API response schemas.
4. Generate Retrofit interfaces and repositories.
5. Generate read-only fragments/adapters before authenticated mutation flows.
6. Add write flows one at a time: auth, create room, post message, reply, vote, edit/delete, profile upload.

Manual verification required:

| Area | Why |
| --- | --- |
| Auth/token lifecycle | Easy to produce insecure or incompatible Android/Django flows. |
| Google auth | Current server config has no client ID; mobile OAuth needs deliberate setup. |
| Off-topic logic | Existing heuristic is simple and may reject valid content. Preserve or intentionally revise. |
| Nested replies | Recursive UI/API shape is easy to mishandle in RecyclerView. |
| Ownership/permissions | Must match web behavior exactly. |
| File uploads | Android multipart and Django media handling need device/server testing. |

Easiest modules to generate: read-only topics, read-only rooms, read-only activity, static profile detail.

Most mistake-prone modules: authentication, Google sign-in, threaded message rendering, voting state, off-topic moderation feedback, multipart avatar upload.

## 22. Known Issues

| Category | Issue |
| --- | --- |
| Security | `SECRET_KEY` is committed in settings; `DEBUG=True`; `ALLOWED_HOSTS=[]`; `CORS_ALLOW_ALL_ORIGINS=True`; session cookie secure disabled. |
| Security | Logout is a GET route. |
| Security | Public API exposes room `fields='__all__'` with raw foreign key ids and no permissions. |
| Auth | Google provider `client_id` is empty in settings. |
| Email | allauth email verification is optional but no email backend is configured. |
| Data integrity | `Topic.name` and `Hub.name` are not unique, but create/update uses `get_or_create(name=...)`; duplicate names can still exist through admin or prior data. |
| Data integrity | `Hub.slug` is unique but not auto-generated by source code. |
| Null handling | Templates assume `room.host.avatar.url`, `room.host.username`, and topic names exist even though room host/topic can be null. |
| API | Existing room API does not include nested host/topic display data, message lists, auth, pagination, or write endpoints. |
| UI/template | `base/templates/base/activity.html` contains duplicated/corrupted trailing markup after a complete page block. |
| Tests | No meaningful automated tests are present. |
| Performance | Recursive replies and score properties can create many database queries; no `select_related`/`prefetch_related` is used. |
| UX/business logic | Vote action cannot toggle a vote back to neutral. |
| UX/business logic | Off-topic filter depends on hardcoded English token/synonym matching. |
| Static/media | Uploaded media is stored under `static/images`, which mixes static assets with user uploads. |
| Admin | `Hub` is not registered in admin. |
| Code cleanliness | `createRoom` and `updateRoom` each have duplicate `@login_required` decorators. |

Time estimates:

| Scope | Estimate |
| --- | --- |
| MVP Android app | 3-5 weeks for one developer/AI-assisted workflow, assuming backend API work is included and Google auth can be postponed. |
| Full-feature Android app | 6-9 weeks including robust auth, write flows, image upload, nested replies, permissions, pagination, tests, and polish. |

Easiest features:

- Read-only topic browsing.
- Read-only room list/search.
- Read-only activity feed.
- User profile display.

Hardest features:

- Token auth and secure Android session handling.
- Google sign-in parity with allauth.
- Nested threaded messages in RecyclerView.
- Avatar upload and media URL handling.
- Preserving off-topic moderation feedback in API responses.

Biggest technical risks:

- Building Android before the REST API contract is stable.
- Reusing session/CSRF auth instead of token auth for native Android.
- Under-fetching display data with raw `RoomSerializer(fields='__all__')`.
- Performance problems from unoptimized nested messages and vote counts.
- Mixing user uploads into the static images directory in production.

Postpone if time is limited:

- Google sign-in.
- Hub following, because no current web flow implements follow/unfollow.
- Offline caching.
- Advanced moderation tools.
- Vote neutral/toggle enhancements, unless product behavior requires them.
